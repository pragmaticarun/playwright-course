# Playwright Bench

A hands-on Playwright course for Arunkumar: an Ubuntu developer who already writes C++, Rust, and Android code and wants the same kind of precision from browser automation.

Thirty-eight lessons. Each one starts with the idea, then a small example, then exercises with hints and solutions, then a quiz. The examples run against Workshop Bench, a local practice app with no database and a fixture login that is not a real credential.

## Run the course site

```bash
npm ci
npm run dev
```

The site listens on [http://127.0.0.1:43123](http://127.0.0.1:43123). Search, the lesson list, dark mode, and progress all stay in the browser. There is no account.

A production build is a static export:

```bash
npm run build
```

The files land in `out/`. `BASE_PATH` is optional and is how GitHub project sites get a prefix. See [docs/github-pages.md](docs/github-pages.md).

## Run the lab and the tests

```bash
npm run practice
npm test
```

`npm run practice` serves Workshop Bench on `http://127.0.0.1:4471`. `npm test` starts that server itself, so you can skip the first command. The suite is Chromium for every spec, and Firefox and WebKit for tests tagged `@cross`.

```bash
npm run validate
npm run test:site
```

`validate` checks the lesson files. `test:site` drives the course site on port 43123 and expects `npm run dev` to be up, or starts it.

Pins, browsers, and the last local run are in [docs/VERSIONS.md](docs/VERSIONS.md).

## What is in the tree

| Path | What it is |
| --- | --- |
| `content/lessons` | The 38 lessons |
| `practice-app` | Workshop Bench |
| `tests` | Example specs |
| `projects` | Three drills and the capstone |
| `app`, `components`, `lib` | The static course site |
| `.github/workflows` | Playwright CI and a GitHub Pages deploy |

The fixture account is `maintainer` / `shelf-note`. The cookie file under `playwright/.auth` is generated by the setup project and is gitignored.

## GitHub Pages

The deploy workflow is ready. This project does not publish a live site by itself. You still need a GitHub repository you control, Pages set to GitHub Actions, and a successful deploy job. Use the URL that job prints. Do not reuse this tree to change an unrelated repository.
